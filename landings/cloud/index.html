Capabilities

The boring parts of production, handled

Build, supervision, routing, and quotas are separate packages with one job each — so failures stay contained and upgrades stay predictable.

Multi-tenant control plane

Tenants, projects, environments, and deployment history live in one store with tenant-scoped reads and quota enforcement.

Hermetic builds

Every release is compiled with CGO_ENABLED=0, trimmed, and stripped — a static binary with no host toolchain surprises.

Supervised processes

Port allocation, active health probes, crash detection, bounded restarts, and memory ceilings for every workload.

Zero-downtime releases

Blue/green swap: the new release must pass its health probe before routing changes, then the old one drains with SIGTERM.

Host-based gateway

Register a hostname and internal port at deploy time. The edge proxy hot-reloads routes and owns TLS termination.

Quotas & metering

Plan limits for projects, memory, and bandwidth are evaluated per tenant, with usage records ready for billing.

Pipeline

A release is a sequence you can read

Nothing is hidden behind a black box. Each stage writes a log line and a deployment status you can query.

  • Builds and releases are recorded per commit, per tenant.
  • Failed health probes never receive traffic.
  • Logs stream live to the console and persist for later inspection.
  1. Connect Point a project at a repository, or trigger a deploy from the CLI, API, or a signed git push.
  2. Build The runner compiles a static binary and streams every line back to the deployment record.
  3. Swap A fresh port is probed before the gateway is updated, so in-flight traffic never hits a cold process.
  4. Observe Status, logs, and resource usage stay queryable; the previous release drains gracefully.
